# 淘沙分析平台 - 项目介绍大纲

## 1. 项目背景和目标

### 1.1 业务背景
- **数据分析门槛高**：业务人员需要依赖技术人员写SQL查询数据
- **响应效率低**：从需求提出到获得数据分析结果周期长
- **重复工作多**：相似的查询需求反复开发
- **数据理解困难**：业务人员难以理解复杂的表结构和字段含义

### 1.2 项目目标
- **降低使用门槛**：让业务人员用自然语言直接查询数据
- **提升响应速度**：秒级响应常见分析需求
- **智能化分析**：AI理解业务语义，自动生成准确SQL
- **企业级部署**：支持内网环境，保障数据安全

## 2. 技术难点

### 2.1 自然语言理解难点
- **语义歧义性**：同一句话可能有多种理解方式
- **业务术语映射**：业务语言与数据库字段的对应关系
- **复杂查询逻辑**：多表关联、聚合计算、时间范围等复杂业务逻辑

### 2.2 SQL生成准确性
- **表结构复杂**：多表关联、字段类型不一致
- **数据质量问题**：存储类型与业务类型不匹配
- **性能优化**：生成的SQL需要考虑执行效率

### 2.3 企业环境适配
- **内网部署要求**：无法依赖外部API服务
- **数据安全**：敏感数据不能外传
- **系统集成**：需要与现有Hadoop/Spark环境集成

## 3. 解决方案

### 3.1 技术选型策略
- **专业NL2SQL引擎**：选择Vanna框架，专门针对自然语言转SQL优化
- **多轮对话管理**：使用LangGraph管理复杂交互流程
- **本地化部署**：支持内网VLLM模型，避免数据外传
- **轻量级OLAP**：DuckDB作为查询加速层

### 3.2 核心解决思路
- **语义增强**：通过元数据管理和术语表建立业务语义映射
- **上下文学习**：利用向量数据库存储查询模式，提升准确性
- **渐进式优化**：通过用户反馈持续改进模型效果
- **分层架构**：热点数据缓存 + 离线数据查询的混合架构

## 4. 技术架构

### 4.1 整体架构
```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   前端界面      │    │   后端服务      │    │   数据层        │
│                 │    │                 │    │                 │
│ • Vue/React     │◄──►│ • FastAPI       │◄──►│ • Hadoop/Spark  │
│ • Streamlit     │    │ • LangGraph     │    │ • DuckDB缓存    │
│   (原型)        │    │ • Vanna引擎     │    │ • 元数据库      │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### 4.2 核心组件
- **LangGraph**：多轮对话管理、工作流编排、交互记录
- **Vanna引擎**：专业NL2SQL转换、向量数据库、模式学习
- **DuckDB**：嵌入式OLAP引擎、热点数据缓存
- **元数据管理**：表结构、字段映射、业务术语

### 4.3 数据流转
```
原始数据(Hadoop) → ETL处理(Spark) → 热点缓存(DuckDB) → 查询结果
                                   ↑
                             cachetools内存缓存
```

## 5. 核心能力

### 5.1 智能语言理解
- **业务术语识别**：自动识别和映射业务专有名词
- **时间语义解析**：理解"最近30天"、"本月"等时间表述
- **聚合逻辑推理**：自动推断求和、平均、分组等统计需求

### 5.2 精准SQL生成
- **多表关联**：根据关联配置自动处理表间关系
- **类型转换**：自动处理存储类型与业务类型的差异
- **性能优化**：生成索引友好的查询语句

### 5.3 查询性能优化
- **三层缓存策略**：
  - L1: 内存缓存(cachetools) - 毫秒级
  - L2: DuckDB缓存 - 秒级
  - L3: Spark查询 - 分钟级

### 5.4 智能交互
- **澄清机制**：当查询不明确时主动询问
- **建议引导**：提供具体的查询示例
- **错误重试**：自动修正SQL错误并重新执行

## 6. 核心流程

### 6.1 查询处理流程
```
用户输入自然语言
        ↓
    输入清晰度验证
        ↓
   [不清晰] → 提供建议示例
        ↓
   [清晰] → Vanna生成SQL
        ↓
    SQL执行(三层缓存)
        ↓
   [失败] → 错误分析重试
        ↓
   [成功] → 返回结果和可视化
```

### 6.2 模型训练流程
```
元数据变更检测
        ↓
    重新训练Vanna模型
        ↓
    更新向量数据库
        ↓
    验证查询效果
```

### 6.3 缓存更新流程
```
数据源更新 → 缓存失效检测 → 增量更新DuckDB → 清理过期缓存
```
