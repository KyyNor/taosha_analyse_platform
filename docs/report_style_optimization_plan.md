# 数据分析报告样式优化方案 (方案二)

## 核心思路
将“视觉设计”与“内容生成”解耦。在外网预先设计多套专业的数据看板 CSS 样式，内网 Agent 在生成 HTML 报告时，仅需遵循预定义的 HTML 结构和 Class 类名，由系统在渲染阶段统一注入全局样式表。

## 关键步骤

### 1. 定义样式标准 (Style Guide)
*   设计一套名为 `taosha-report.css` 的专业样式表。
*   **核心组件化**：定义 `.report-container` (容器), `.metric-card` (指标卡), `.data-table` (表格), `.insight-box` (结论框), `.chart-wrapper` (图表容器) 等标准类。
*   **设计风格**：采用现代商业 BI 风格（如：毛玻璃效果、优雅的阴影、清晰的排版层级）。

### 2. 优化 Agent 提示词 (Prompt Refinement)
*   在 `DataAnalyserAgent` 的系统提示词中加入“组件说明书”。
*   **约束**：禁止 Agent 生成内联样式 (`style="..."`)，强制要求使用预定义的类名。
*   **示例**：给模型提供一个标准的 HTML 骨架代码片段作为参考。

### 3. 后端样式注入 (Style Injection)
*   生成的 `report.html` 不再是孤立文件。
*   后端在保存报告前，自动在 `<head>` 中注入全局样式链接和必要的基础脚本（如：用于表格排序的小型 JS）。
*   支持通过配置文件或参数切换不同的样式模板（Theme）。

## 方案优势
*   **视觉专业化**：彻底消除“AI 风格”，确保报告达到商业级 UI 水准。
*   **生成稳定性**：HTML 结构固定，减少了因 AI 自由发挥导致的样式崩坏。
*   **性能提升**：减少了 LLM 输出的 Token 数量，响应速度更快。
*   **低耦合**：样式迭代与模型逻辑完全分离，前端工程师可独立优化 CSS。

## 适用性评估
对于 **GLM-4.5 (100B)** 级别的模型，其强大的指令遵循能力可以精准地将内容填充到指定的 HTML 结构中，是该方案的最佳实践对象。
