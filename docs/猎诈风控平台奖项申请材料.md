# 猎诈风控平台（FraudHunter）奖项申请材料

## 一、项目实施内容

### 1.1 项目背景

传统反诈模型的开发、调试、部署流程存在以下痛点：

- **开发周期长**：运营管理部每次需求变更都需要依赖信息科技部支持，从需求提出到模型上线需要数周时间
- **调试效率低**：单次模型回测需要半天到数小时，严重影响模型迭代速度
- **人员依赖强**：业务人员无法独立完成模型设计和验证，必须依赖技术人员协助
- **维护成本高**：模型规则硬编码在代码中，变更需要走完整的开发-测试-部署流程

### 1.2 项目目标

构建一个**让运营管理部可以独立开发、调试、部署反诈模型**的智能风控平台，实现：

- 业务人员**零代码**配置复杂风控规则
- 模型回测时间从**数小时**降低到**几分钟**
- 完全**不依赖**信息科技部人员的日常模型运维
- 支持**实时+离线**双轨指标计算能力

### 1.3 系统架构

猎诈风控平台采用**四层架构设计**：

```
┌─────────────────────────────────────────────────────────────────┐
│                        告警层                                    │
│  · 实时告警生成  · 管控记录追踪  · Excel批量导出  · 重复检测     │
├─────────────────────────────────────────────────────────────────┤
│                        模型层                                    │
│  · 可视化规则引擎  · SQL自动生成  · 历史回测  · 模型版本管理     │
├─────────────────────────────────────────────────────────────────┤
│                        宽表层                                    │
│  · 智能双版本机制  · 离线宽表(T+1)  · 实时宽表  · 自动降级      │
├─────────────────────────────────────────────────────────────────┤
│                        指标层                                    │
│  · 指标定义管理  · 指标任务编排  · 批量创建  · 版本追踪          │
└─────────────────────────────────────────────────────────────────┘
```

### 1.4 核心模块实现

#### 1.4.1 指标管理模块

- **指标定义**：支持整数、浮点数、字符串、日期等多种数据类型
- **对象类型**：支持客户号（cust_no）、存款账号（dep_acct_no）、贷款账号（loan_acct_no）
- **自动编码**：根据指标类型和对象类型自动生成唯一编码
- **版本管理**：双版本追踪（当前发布版本 + 最新修改版本）
- **批量创建**：分步骤UI引导，支持一次创建多达50个指标

#### 1.4.2 指标任务模块

- **SQL加工管理**：存储离线SQL和实时SQL两套逻辑
- **DolphinScheduler集成**：一键发布到调度平台
- **预执行验证**：提交前自动验证SQL语法和字段映射
- **版本同步**：任务更新时自动同步关联指标版本

#### 1.4.3 可视化规则引擎

- **无限层级嵌套**：支持AND/OR逻辑的多层规则组
- **丰富的运算符**：支持12种运算符（=、!=、>、<、in、between、regexp等）
- **5种值表达式**：
  - 常量值（固定数值/字符串）
  - 指标间对比（同类型指标比较）
  - 时间函数（DATE_ADD/DATE_SUB）
  - 数学函数（ABS绝对值）
  - 相对计算（加减乘除）
- **实时SQL预览**：配置即可见生成的SQL语句
- **规则导入导出**：JSON格式规则复用

#### 1.4.4 智能双版本宽表

- **离线宽表**：T+1全量更新，Parquet列式存储
- **实时宽表**：基于Kafka Canal实时增量更新
- **版本哈希**：SHA256生成版本标识，确保数据一致性
- **自动降级**：实时数据异常时自动降级到离线版本
- **快照追踪**：完整的版本变更历史记录

#### 1.4.5 模型回测系统

- **历史数据回测**：指定时间范围验证模型效果
- **高性能计算**：DuckDB内存引擎秒级返回结果
- **结果导出**：Excel格式导出回测命中记录
- **版本降级追踪**：记录回测中的指标版本降级情况

#### 1.4.6 告警管控系统

- **命中记录生成**：实时记录模型匹配结果
- **重复检测**：智能识别重复告警避免骚扰
- **批量导出**：支持Excel批量导出管控记录
- **全生命周期追踪**：从命中到管控的完整记录

## 二、应用场景

### 2.1 反诈模型快速迭代

**场景描述**：运营管理部发现新型诈骗手法，需要快速上线对应的识别模型。

**传统方式**：
1. 业务人员提需求给科技部（1-2天）
2. 科技人员开发模型代码（3-5天）
3. 测试环境验证（1-2天）
4. 上线部署（1天）
5. **总耗时：1-2周**

**使用猎诈平台**：
1. 业务人员登录平台，创建新模型
2. 使用可视化规则构建器配置规则
3. 点击"回测"验证模型效果
4. 确认无误后一键发布上线
5. **总耗时：30分钟至2小时**

### 2.2 模型规则调优

**场景描述**：某反诈模型误报率过高，需要调整阈值参数。

**使用猎诈平台**：
1. 进入模型详情页
2. 修改规则中的阈值（如将"单日交易金额 > 50000"调整为"> 80000"）
3. 选择历史时间范围进行回测
4. 对比调整前后的命中率和误报率
5. 确认效果后保存并发布新版本

**优势**：整个过程业务人员独立完成，无需任何技术支持。

### 2.3 复杂规则组合

**场景描述**：需要识别"高龄客户+大额转账+新开户"的组合风险场景。

**规则配置示例**：
```
AND (满足以下全部条件)
├── 客户年龄 > 60
├── OR (满足以下任一条件)
│   ├── 单笔转账金额 > 100000
│   └── 当日累计转账 > 300000
└── 开户天数 < 30
```

**平台实现**：通过可视化规则构建器，拖拽配置即可完成上述复杂规则，无需编写任何代码。

### 2.4 实时风控拦截

**场景描述**：客户发起大额转账交易，需要实时判断是否触发风控规则。

**数据流程**：
1. 交易系统发送交易数据到Kafka
2. 猎诈平台消费数据，计算实时指标
3. 实时指标与离线宽表合并
4. 执行规则匹配
5. 命中规则则生成告警并触发管控

**响应时间**：毫秒级响应，支持实时拦截。

### 2.5 批量指标上线

**场景描述**：新业务需求需要一次性创建20个风控指标。

**平台支持**：
1. 进入"批量创建"页面
2. 选择指标类型和对象类型
3. 批量输入指标名称和定义
4. 配置统一的SQL任务
5. 预执行验证确认
6. 一键创建完成

**效率提升**：从逐个创建的数小时缩短到30分钟内完成。

### 4.2 技术创新点详解

#### 4.2.1 DuckDB内存计算引擎

**创新应用**：将DuckDB嵌入式OLAP数据库应用于模型回测场景。

**技术优势**：
- **零配置部署**：无需独立数据库服务，嵌入应用进程
- **列式存储优化**：针对分析型查询优化，扫描速度快
- **Parquet原生支持**：直接读取Parquet文件，无需数据导入
- **内存计算**：数据加载到内存后执行，响应时间毫秒级

**性能提升**：模型回测从传统Spark批处理的**数小时**降低到**几分钟**。

```python
# 示例：DuckDB直接读取Parquet进行回测
SELECT target_id, indicators...
FROM read_parquet('wide_table_20251226.parquet') as offline
LEFT JOIN read_parquet('realtime_20251226.parquet') as realtime
WHERE (rule_conditions)
LIMIT 10000
```

#### 4.2.2 递归规则引擎

**创新设计**：支持无限层级嵌套的规则树结构和递归SQL生成。

**技术实现**：
```python
# 规则树结构
RuleConfig:
  logic: AND | OR
  rules: List[ConditionRule | GroupRule]  # 递归嵌套

# 递归SQL生成
def build_sql(rule):
    if isinstance(rule, ConditionRule):
        return build_condition_sql(rule)
    elif isinstance(rule, GroupRule):
        sub_sqls = [build_sql(r) for r in rule.rules]
        return f"({f' {rule.logic} '.join(sub_sqls)})"
```

**创新点**：
- 支持任意深度的规则嵌套
- 自动类型推断和兼容性检查
- 左元素函数支持（如ABS）
- 5种右值表达式类型

#### 4.2.3 智能版本哈希算法

**创新设计**：基于指标ID和版本号生成宽表版本哈希。

**技术实现**：
```python
def generate_version_hash(indicators):
    # 将指标ID和版本号拼接
    version_string = '#'.join([
        f"{i.id}_{i.current_version}"
        for i in sorted(indicators, key=lambda x: x.id)
    ])
    # SHA256哈希取前8位
    return hashlib.sha256(version_string.encode()).hexdigest()[:8]
```

**技术优势**：
- 确保宽表版本与指标版本一致性
- 快速检测指标变更
- 支持版本回溯和对比

#### 4.2.4 实时宽表合并算法

**创新设计**：实时指标与离线宽表的智能合并策略。

**技术实现**：
```sql
-- 实时宽表生成SQL
SELECT
    realtime.target_id,
    realtime.etl_date,
    -- 实时指标
    realtime.indicator_1,
    realtime.indicator_2,
    -- 离线指标（T-1日）
    offline.indicator_3,
    offline.indicator_4
FROM realtime_wide_table AS realtime
LEFT JOIN offline_wide_table AS offline
    ON realtime.target_id = offline.target_id
```

**智能降级**：
- 检测指标版本匹配状态
- 自动降级到target版本或current版本
- 记录降级原因和影响范围

#### 4.2.5 指标别名自动映射

**创新设计**：根据指标编码前缀自动映射数据源表别名。

**映射规则**：
```python
INDICATOR_ALIAS_MAP = {
    'realtime': 'dep_acct_realtime_indicator',
    'cust_': 'cust_offline_indicator',
    'default': 'dep_acct_offline_indicator'
}

# 生成的SQL示例
WHERE dep_acct_realtime_indicator.daily_amount > 50000
  AND cust_offline_indicator.age > 60
  AND dep_acct_offline_indicator.account_balance > 100000
```

**技术优势**：业务人员无需了解底层表结构，系统自动处理表关联。
