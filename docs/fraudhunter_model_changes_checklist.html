FraudHunter 模型能力改动检查清单

用于检查本次模型相关能力改动：批量模型回测、前缀模型引用、模型上线时间展示。 建议按模块逐块验证，先确认数据库和后端启动，再检查页面流程和结果导出。

适用模块：FraudHunter 预警管控模型 检查方式：功能走查 + 构建验证 文档日期：2026-06-12
批量回测 1 个批量父任务 + N 个普通模型回测子任务，父任务只展示固定汇总结构。
前缀模型 前缀模型作为公共规则片段被普通模型引用，不独立触发告警和管控。
上线时间 模型发布时记录上线人和上线时间，并在列表与详情页展示。

1. 后端启动与数据库结构

优先级：必须先检查
  • 重启后端服务，确认启动日志中没有数据库迁移、建表或索引创建报错。
  • 确认旧库自动补齐字段：fraudhunter_dryrun_execution.parent_execution_id。
  • 确认旧库自动补齐字段：fraudhunter_model_definition.model_type。
  • 确认旧库自动补齐字段：fraudhunter_model_definition.online_at。
  • 确认旧库自动补齐字段：fraudhunter_model_definition.online_by。
  • 确认索引存在：idx_fh_dryrun_parent_execution_id 和 idx_fh_model_type。
如果数据库账号没有 ALTER TABLE 或 CREATE INDEX 权限，启动可能失败。 这种情况下需要让 DBA 手动执行对应 DDL。

2. 批量模型回测提交

路径：预警管控模型管理
  • 进入“预警管控模型管理”页面，确认表格左侧出现模型勾选列。
  • 选择多个普通模型，点击“批量回测”。
  • 选择开始日期和结束日期，提交批量回测任务。
  • 提交成功后进入“试运行任务”页面。
  • 确认出现 1 个 批量模型回测 父任务。
  • 确认出现 N 个 模型历史回测 子任务。
  • 确认子任务列表中的“父任务”列显示父批量任务的执行 ID。

3. 批量回测结果页

路径：试运行任务详情
  • 打开批量回测父任务详情页。
  • 确认概览卡片展示：模型数、成功模型数、失败模型数、命中账号数、命中记录数。
  • 确认“账号命中汇总”表正常展示账号、命中模型数、命中模型、命中日期、白名单标记。
  • 确认“模型执行汇总”表正常展示每个模型的执行状态和命中统计。
  • 从“模型执行汇总”或“账号命中汇总”的模型入口跳转到对应子任务，确认跳转正常。
  • 确认“每日汇总”表按日期展示成功模型、失败模型、跳过模型、命中账号和命中记录。
  • 点击导出 Excel，确认文件可下载，且包含账号、模型、每日、失败和警告相关 Sheet。

4. 单模型回测回归

确认旧流程不退化
  • 打开任意批量回测子任务详情。
  • 确认单模型回测仍按原有动态列展示命中记录。
  • 确认单模型的每日执行详情、警告信息、执行日志仍正常展示。
  • 点击单模型结果导出 Excel，确认导出结果不受批量回测改动影响。

5. 前缀模型创建与引用

核心新增能力
  • 新建模型时选择“前缀模型”。
  • 确认前缀模型页面不展示或不启用告警配置和账户管控配置。
  • 给前缀模型配置一组公共规则并保存。
  • 发布该前缀模型，确认状态变为在线。
  • 新建或编辑普通模型，在规则配置中添加“前缀模型”节点。
  • 选择刚刚发布的前缀模型，保存普通模型。
  • 点击规则 SQL 预览，确认前缀模型中的公共规则被展开进最终 SQL。
  • 尝试引用非前缀模型，确认后端校验会拒绝或提示错误。
前缀模型本身不会被实时调度作为独立模型执行。它只作为规则片段被普通模型引用。

6. 模型上线时间

审计字段检查
  • 发布一个普通模型，确认发布接口返回成功。
  • 回到模型列表，确认“上线时间”列有值。
  • 打开模型详情页，确认审计信息中展示“上线人”和“上线时间”。
  • 检查历史已上线但未重新发布的模型：允许上线时间为空。
  • 重新发布历史模型后，确认上线时间被写入当前发布时间。

7. 回归与异常口径

收尾检查
  • 普通模型创建、编辑、发布流程仍正常。
  • 普通模型单模型回测仍正常。
  • 批量回测中某个子模型失败时，父任务仍能展示其他模型的聚合结果。
  • 实时调度只执行 model_type = normal 的在线模型，不执行前缀模型本身。
  • 如果批量结果为空，确认页面展示为空态，而不是报错。
  • 如果引用的前缀模型不存在或形成循环引用，确认规则校验返回明确错误。

8. 建议执行的验证命令

开发环境
  • 后端语法检查：uv run python -m py_compile ...
  • 前端类型检查：cd frontend && npx tsc --noEmit
  • 前端生产构建：cd frontend && npm run build
  • 如项目后续配置了 ESLint，再执行：cd frontend && npm run lint

通过标准：核心链路可提交、可执行、可查看、可导出；旧的单模型回测展示不退化。
