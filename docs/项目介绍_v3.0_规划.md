## 详细内容规划

### 1. 问题背景 (section-problem)

#### 核心矛盾
- 主要矛盾：业务部门日益增长的数据处理需求与相对固定的数据服务产出能力的矛盾

#### 具体表现
- **技术门槛高**：业务人员缺乏SQL技能，数据分析完全依赖技术人员
- **响应效率低**：传统报表开发周期长，无法满足快速变化的业务需求
- **数据孤岛**：缺乏统一的数据分析平台，数据分散在各个系统中

### 2. 解决方案 (section-solution)

#### 项目目的
- 利用大模型及完善基础设施（历史的数据工厂项目），提供自然语言的查询能力

#### 核心价值
- **零技术门槛**：业务人员用自然语言提问，系统自动生成并执行SQL查询
- **智能交互体验**：基于LangGraph智能工作流，人在循环交互，确保查询准确性
- **自动化数据管理**：智能元数据同步，减少人工维护成本

### 3. 服务模式 (section-service-modes)

#### 模式1：面向业务部门-常用报表智能化改造
- 新增一个智能检索页面
- 允许用户在一个虚拟表（主报表的查询语句，附带主报表的权限控制）上用自然语言筛选、查询、分析

#### 模式2：面向科技部门-数据团队辅助编码
- 在接到数据处理需求后，先利用淘沙做一个基础SQL的构建
- 提高数据开发效率，减少重复工作

#### 模式3：面向业务部门-业务团队自助分析
- 允许业务人员自助在权限范围内做数据检索、分析
- 提高业务自主性，减少对技术部门的依赖

### 4. 技术架构 (section-tech-architecture)

#### 整体架构
- **后台**：Python，提供独立页面
- **元数据同步**：从数据工厂定期同步
- **知识库存储**：训练的知识库存储到Qdrant向量数据库中
- **执行引擎**：备集群Spark，可拓展MySQL等其他引擎

#### 架构图设计
- 前端展示层：Vue 3 + TypeScript + Vite
- API服务层：Python + FastAPI + SQLAlchemy
- 数据存储层：SparkSQL + MySQL + Qdrant

### 5. 面临问题及解决方案 (section-challenges-solutions)

#### 5.1 锁定查询范围
- **问题**：对于用户的自然语言输入，如何在数据工厂的2500张表中精准命中用户实际需要的表？
- **解决方案**：
  - 方案一（当前方案）：构建数据主题，每个主题包括相关表20张以内，用户查询前需要先选择查询的目标主题，检索范围限制在选择主题的表范围内
  - 方案二：按Hadoop数据血缘、Hadoop-Mysql数据同步、Mysql-帆软CPT血缘关系、帆软CPT访问量综合评估每张表的引用计数，在向量检索时按引用计数增加表权重，引用计数为0的表不参与检索

#### 5.2 如何确保用户输入清晰
- **问题**：用户使用自然语言输入时，很有可能其输入不完整，不清晰，如何发现这种问题，并反馈到用户补充信息？
- **解决方案**：（人在循环）在工作流中设置清晰度验证节点，大模型结合已有表信息判断用户输入是否清晰，如果不清晰，则反馈给用户补充。

#### 5.3 业务逻辑确定
- **问题**：如何通过用户自然语言输入确认其业务描述所对应的数据字段及查询逻辑？
- **解决方案**：
  - **知识库**：
    - 术语解释：对内部术语给出明确的解释说明，最好精确到查询条件
    - SQL问答：将日常数据加工、取数的SQL以问答的形式维护进来
    - 数据字典：常用字段的字典映射关系
  - **关联关系**：对于可以关联的字段，标记其关联ID，并对关联ID的关联方式做解释说明

#### 5.4 资源隔离
- **问题**：淘沙查询需依赖Spark集群，而Spark生产集群需要执行数据处理任务，需防止淘沙应用阻塞正常数据加工
- **解决方案**：由于任务执行的时候有明显的木桶效应，新老集群混用在任务数量中等偏少的场景，如果任务分配到了老节点，并无法显著提升运行效率。因此将Spark集群拆分为老集群bigdata01~bigdata06和新集群bigdata07~bigdata10，Hadoop集群维持不变，数据处理任务在新集群运行，淘沙任务、数据同步任务在老集群运行。

#### 5.5 权限控制
- **问题**：如何控制用户可以查询的数据范围？
- **解决方案**：
  1. 对于常用报表的智能化改造场景，提供给淘沙的就是一张虚拟表，可以是视图，也可以在下发查询之前替换为一个子查询，这个查询语句是附带权限控制的，因此最终查询结果也是有权限控制的
  2. 指定吸存码、机构号等字段为权限字段，按帆软角色配置用户查询范围，所有涉及到此类字段的在SQL生成完毕后包一层权限控制。
