# 模型执行跟踪系统需求文档

## 介绍

模型执行跟踪系统用于记录和管理风控模型的运行结果，包括命中记录的存储、告警与管控的自动化处理，以及相关数据的查询展示功能。

## 术语表

- **模型执行跟踪系统 (Model_Execution_Tracking_System)**: 负责记录模型运行命中情况和处理告警管控的完整系统
- **命中记录 (Hit_Record)**: 单次模型运行中账号命中模型的详细记录
- **告警管控记录 (Alert_Control_Record)**: 基于命中记录生成的告警和管控处理记录
- **账号 (Account)**: 被模型检测的目标账户标识
- **模型 (Model)**: 风控检测模型，可配置为告警模型或告警+管控模型
- **指标信息 (Indicator_Data)**: 模型运行时计算得出的各项指标数值
- **去重逻辑 (Deduplication_Logic)**: 防止同一账号在同一天内重复告警或管控的业务规则
- **管控流水号 (Control_Serial_Number)**: 管控操作的唯一标识号

## 需求

### 需求 1

**用户故事:** 作为系统管理员，我希望系统能够自动记录模型运行的命中情况，以便追踪和分析模型的执行效果。

#### 验收标准

1. 当定时任务触发模型运行时，模型执行跟踪系统应当为每个命中的账号创建命中记录
2. 当账号命中多个模型时，模型执行跟踪系统应当在单条记录中存储所有命中的模型信息
3. 当同一账号在同一天多次命中相同模型时，模型执行跟踪系统应当创建多条独立的命中记录
4. 当创建命中记录时，模型执行跟踪系统应当存储账号标识、指标数据、命中模型ID列表、命中模型名称列表和命中时间
5. 当存储指标数据时，模型执行跟踪系统应当使用JSON格式保存所有指标信息

### 需求 2

**用户故事:** 作为风控人员，我希望系统能够基于命中记录自动处理告警和管控，以便及时响应风险事件。

#### 验收标准

1. 当创建命中记录后，模型执行跟踪系统应当自动生成对应的告警管控记录
2. 当账号首次命中告警模型时，模型执行跟踪系统应当发送格式为"账户 {账号} 在 {时间}，因命中{模型列表}模型，触发告警"的告警消息并记录告警信息
3. 当账号在同一天内再次命中已告警过的模型时，模型执行跟踪系统应当标记为重复告警、记录告警消息内容但不发送实际告警消息
4. 当账号命中管控模型且当天未被管控过时，模型执行跟踪系统应当发送格式为"账户 {账号} 在 {时间}，因命中{模型列表}模型，触发告警及管控"的告警消息、执行管控操作并记录管控信息
5. 当账号在同一天内再次命中管控模型时，模型执行跟踪系统应当标记为重复管控且不执行实际管控操作

### 需求 3

**用户故事:** 作为风控分析师，我希望能够查看和分析命中记录，以便了解模型的运行情况和效果。

#### 验收标准

1. 当用户访问命中记录页面时，模型执行跟踪系统应当显示包含账号、命中时间、命中模型和指标信息的记录列表
2. 当用户筛选命中记录时，模型执行跟踪系统应当支持按日期范围、账号和模型进行过滤
3. 当用户查看命中记录详情时，模型执行跟踪系统应当展示完整的指标数据和命中模型信息
4. 当用户导出命中记录时，模型执行跟踪系统应当提供CSV或Excel格式的数据导出功能
5. 当显示大量记录时，模型执行跟踪系统应当提供分页功能以优化页面性能

### 需求 4

**用户故事:** 作为风控管理员，我希望能够查看和管理告警管控记录，以便监控系统的告警和管控执行情况。

#### 验收标准

1. 当用户访问告警管控记录页面时，模型执行跟踪系统应当显示包含账号、日期、模型信息、告警状态和管控状态的记录列表
2. 当用户筛选告警管控记录时，模型执行跟踪系统应当支持按日期范围、账号、模型和处理状态进行过滤
3. 当用户查看告警详情时，模型执行跟踪系统应当显示告警消息内容、告警人和告警时间
4. 当用户查看管控详情时，模型执行跟踪系统应当显示管控时间和管控流水号
5. 当用户需要统计分析时，模型执行跟踪系统应当提供告警和管控的统计图表功能

### 需求 5

**用户故事:** 作为系统开发人员，我希望系统具有良好的数据存储结构，以便支持高效的查询和扩展。

#### 验收标准

1. 当设计命中记录表时，模型执行跟踪系统应当支持灵活的指标数据存储和多模型信息存储
2. 当设计告警管控记录表时，模型执行跟踪系统应当确保与命中记录的关联关系完整性
3. 当执行数据库查询时，模型执行跟踪系统应当在关键字段上创建适当的索引以优化查询性能
4. 当处理并发访问时，模型执行跟踪系统应当确保数据的一致性和完整性
5. 当系统扩展时，模型执行跟踪系统应当支持新增字段而不影响现有功能
